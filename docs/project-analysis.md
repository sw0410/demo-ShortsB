# shortB React 프로젝트 분석과 데모 로그인

분석 기준: 2026-10-31. 작업 대상은 `shortB-react-source/src`의 React + TypeScript 소스다.

## 1. 프로젝트 구조

이 프로젝트는 React 19, TypeScript, Vite를 사용하는 독서 앱이다. 별도 라우터 라이브러리 없이 React 상태와 브라우저 History API로 화면을 전환한다. `.html`은 화면 주소 규칙이며, 각 주소의 실제 화면은 React 컴포넌트다.

| 파일/폴더 | 역할 |
| --- | --- |
| `src/main.tsx` | 개발 시 React 앱을 마운트하고, 빌드 결과에서는 사전 렌더링한 HTML을 hydrate한다. |
| `src/App.tsx` | Provider, 첫 독서 훅, 공통 레이아웃, 페이지 라우터를 조합한다. |
| `src/app/routes.ts` | 경로 목록, URL 해석·생성, 로그인 상태에 따른 시작 화면 결정 |
| `src/app/PageRouter.tsx` | 25개 경로를 React 페이지 컴포넌트와 연결 |
| `src/state/AppContext.tsx` | 앱 상태 복원·저장, 로그인·로그아웃, 화면 이동, 독서 액션 |
| `src/layouts/AppLayout.tsx` | 헤더, 하단 메뉴, 저장 오류 안내, 알림 |
| `src/pages/` | 홈, 본문, 검색, 책장, 달력, 계정, 취향·목표 설정 |
| `src/domain/types.ts` | 책·판본·독서 세션·기록·앱 상태 타입 |
| `src/domain/reading.ts` | 기본 상태, 이전 데이터 변환, 분량 계산, 이어 읽기, 페이지 완료, 기록 집계 |
| `src/domain/storage.ts` | localStorage 복원·저장과 손상 데이터 복구 |
| `src/domain/catalog.ts` | 책 검색, 취향 기반 추천, 연관 작품 추천 |
| `src/hooks/useTrial.ts` | 비로그인 첫 독서의 시작·이어 읽기 |
| `src/hooks/useReadingClock.ts` | 화면 노출·포커스·최근 활동을 고려한 독서 시간 기록 |
| `src/data/` | 화면에서 사용하는 책 데이터·표지 |
| `content-source/` | 원문과 검증된 완성 번역 스냅샷 |
| `scripts/import-content.mjs` | 원문 해시·문단·검수·장 범위 검증 후 앱용 카탈로그 생성 |
| `scripts/build.mjs`, `src/render.tsx` | React 소스로 검토용 정적 HTML과 공통 JS/CSS 생성 |

`.build/render.mjs`와 `dist/`는 빌드 산출물이다. 기능을 바꾸는 원본은 `src/`다. 산출물을 직접 수정할 필요가 없다.

## 2. 화면과 독서 데이터 흐름

홈 사진의 화면은 `src/pages/HomePage.tsx`다. 미완료 독서가 있으면 이어 읽을 책과 진도를 보여주고, 없으면 `recommend()` 결과를 보여준다. 따라서 홈 화면에 표시되는 책·진도는 브라우저에 저장된 기록에 따라 달라진다.

독서 시작은 `startSession()`이 책 ID, 판본, 시작/현재/끝 페이지, 읽기 모드, 스크롤, 세션 토큰을 저장하는 방식이다. `advance()`는 읽은 페이지를 기록하고 마지막 페이지면 세션을 완료한다. 같은 날 같은 판본의 같은 페이지는 중복 집계하지 않는다. 체험 읽기는 `trial` 모드로 두 페이지를 배정한다.

책장에는 읽던 책, 담은 책, 읽은 기록이 있으며 형광펜은 책·판본·페이지·문자 범위와 함께 저장한다. 옛 판본의 페이지 번호를 다른 판본에 그대로 적용하지 않도록 이전 데이터 변환 시 판본을 확인한다. 달력의 발표용 예시와 실제 독서 기록은 구분된다.

추천은 로컬 규칙이다. 입력한 제목·작가, 분위기, 키워드, 좋아요, 독서 이력을 점수에 반영한다. 연관 추천은 현재 책·추천 경로·최근 기록 등을 제외해 같은 책을 반복 연결하지 않는다. 현재 카탈로그는 읽을 수 있는 한국어 판본 7편과 번역 준비 중 4편이다.

## 3. 로그인 상태 저장

이번 구현은 서버 없이 브라우저 저장 공간으로 로그인 상태를 유지하는 데모다. `src/domain/auth.ts`의 지정 계정 `demo@shortb.com` / `Shortb123!` 조합만 허용한다. 기존 앱 상태 안의 `demoAccountComplete`와 `demoUserId`를 함께 저장한다.

```text
localStorage 키: shortb-react-v1
저장되는 JSON 안의 demoAccountComplete:
  true  → 로그인 상태
  false → 비로그인 상태
```

별도 키를 만들지 않아 기존 저장·복원 로직을 그대로 사용한다. `defaults()`는 false를 초기값으로 주고, `migrate()`는 지정 데모 사용자 ID와 로그인 상태를 함께 확인한다. 이전의 임의 정보로 생성한 로그인 상태는 해제하고 독서 기록은 보존한다. 입력한 이메일과 비밀번호는 저장하지 않으며, 지정 데모 ID만 세션 식별 정보로 저장한다. 실제 서버 인증이나 OAuth 요청은 수행하지 않는다.

`AppContext.update()`는 React 상태와 최신 상태 참조를 함께 갱신하고 `persist()`로 저장한다. 최신 상태 참조를 사용하는 이유는 로그인 값을 바꾼 직후 화면 이동에서도 새 로그인 상태를 읽기 위해서다.

저장 데이터가 손상되면 `restore()`는 복구 사본을 보관하고 이전 키 `ilsaeng-iljang-design-v1`도 확인한다. 저장 공간이 막히면 경고를 표시하며, 이 경우 새로고침 뒤 로그인 유지가 보장되지 않는다.

## 4. 이번에 적용한 화면 이동 규칙

| 상황 | 동작 |
| --- | --- |
| 로그인 상태로 `/` 또는 `/index.html` 접속 | `/home.html`로 이동해 첨부한 홈 화면 표시 |
| 지정 데모 계정 로그인 성공 | 로그인 상태와 데모 ID 저장 → 바로 홈 |
| 다른 계정·틀린 비밀번호 | 오류 안내, 로그인 상태 생성 안 함 |
| 소셜 버튼·가입 완료 | 준비 중 안내, 데모 계정 로그인으로 유도 |
| 로그인 상태에서 첫 독서·체험 완료·계정 화면 접속 | 홈으로 이동 |
| 비로그인 첫 방문 | 책 본문 두 페이지 체험 |
| 비로그인 체험 중 재방문 | 기존 체험 책과 위치를 이어 읽기 |
| 비로그인 체험 완료 | 가입·로그인 안내 유지 |
| 안내에서 나중에 하기를 선택 | 3쪽부터 남은 본문을 계속 읽으며 반복 안내하지 않음 |
| 비로그인 회원 화면 직접 접속 | 현재 게스트 독서 흐름으로 이동 |
| 설정에서 로그아웃 | 로그인 상태만 false로 저장 → 비로그인 시작 경로 |

비로그인 체험 완료 화면에는 회원가입, 로그인, '나중에 할게요 · 계속 읽기' 버튼이 있다. 본문 상단에는 로그인·회원가입 버튼이 항상 보인다. 안내를 거절하면 `continueGuestReading()`이 체험 다음 페이지부터 책 끝까지 읽는 세션을 만들고 `guestContinue`를 저장한다. 새로고침해도 위치와 선택을 유지한다. 책이나 추천 대목을 다 읽으면 `/complete.html`로 이동하고 기존의 다른 관점 추천을 표시한다.

`protectedRoutes`는 오늘 읽기·책 찾기·나의 책장과 관련 회원 화면을 보호한다. URL 직접 입력, 해시 주소, 앱 화면 이동, 뒤로/앞으로 이동에 `resolveLocation()` 규칙이 적용된다. 하단 회원 메뉴는 로그인 상태에서만 표시한다. React 화면을 렌더링할 때도 경로를 확인해 저장 상태 복원 전 회원 화면이 잠깐 노출되는 것을 막는다.

`complete`와 `discover`는 게스트가 계속 읽기를 선택했고 완료 기록이 있으며 해당 완료 책을 가리키는 경우 접근을 허용한다. 홈·검색·책장은 계속 차단한다. 게스트 완료 화면과 로그인 사용자 완료 화면은 공통 `RecommendationCard`를 사용한다. 기존 `nextRelations()`의 추천 이유, 두 작품의 관점 비교, 추천 대목 읽기를 그대로 연결하며, 추천 후보가 소진되면 안내를 표시하고 목록 순서로 재추천하지 않는다. 예전 버전의 `/reader.html`에 완료 상태가 남아 있어도 같은 추천 카드를 표시한다.

로그아웃은 독서 기록·취향·체험 완료 여부를 지우지 않는다. 따라서 이미 체험을 마쳤다면 로그아웃 후에는 체험 완료 안내가 나온다. 첫 방문이라면 책 본문부터 시작한다.

핵심 변경은 다음과 같다.

1. `entryRoute()`는 **로그인 여부**로 홈 진입을 결정한다. 취향 설정이나 저장한 책이 있다는 이유만으로 로그인했다고 판단하지 않는다. 게스트 계속 읽기를 선택한 경우에는 본문으로 돌아간다.
2. `resolveLocation()`은 시작 화면과 로그인한 사용자가 볼 필요 없는 안내·계정 화면을 홈으로 연결한다.
3. `AppProvider`는 localStorage를 복원한 뒤 경로를 결정한다. 일반 화면 이동과 뒤로/앞으로 이동에도 같은 규칙을 적용한다.
4. `login(id, password)`은 `authenticateDemo()`로 지정 계정을 검사한 뒤 `demoAccountComplete: true`와 데모 ID를 저장하고 `go("home", undefined, true)`를 실행한다. `replaceState`를 사용해 현재 로그인 화면 주소를 홈으로 교체한다.
5. `AuthPages.tsx`의 이메일 로그인만 `login()`에 연결했다. 가입 완료와 소셜 버튼은 인증을 우회하지 않고 준비 중임을 안내한다. 로그인 후 추천 설정을 먼저 마칠 필요가 없다. 홈의 취향 변경과 목표 설정은 계속 이용할 수 있다.
6. `SettingsPage.tsx`는 로그인 상태에서 로그인·가입 항목 대신 로그아웃을 보여준다.

`docs/login.txt`는 참고 문서이며 실행되는 설정 파일이 아니다. 화면 전환을 실행하는 코드는 위 React 소스에 있다.

## 5. 확인 방법

```sh
npm run dev
```

1. `http://127.0.0.1:5173/`에 접속한다. 비로그인 첫 방문이면 책 본문이 나온다.
2. 본문의 사용자 아이콘 또는 두 페이지 완료 후 로그인 버튼으로 이동한다.
3. 아이디 `demo@shortb.com`, 비밀번호 `Shortb123!`를 입력한다. 다른 조합은 로그인되지 않는다. 소셜 버튼과 신규 가입으로도 로그인을 우회할 수 없다.
4. 로그인하면 `/home.html`이 열린다. 다시 `/`에 접속하거나 새로고침해도 로그인 상태가 유지된다.
5. 나의 책장 → 설정 → 로그아웃으로 비로그인 상태를 확인한다.
6. 비로그인 상태에서 `/home.html`, `/search.html`, `/library.html`에 직접 접속해 독서 흐름으로 돌아가는지 확인한다.
7. 두 페이지 체험 뒤 '나중에 할게요 · 계속 읽기'를 선택해 3쪽부터 이어 읽는다. 본문 상단의 로그인·회원가입 버튼과 새로고침 후 이어 읽기도 확인한다.

`localhost`와 `127.0.0.1`은 localStorage가 다르다. 테스트할 때는 `http://127.0.0.1:5173`으로 통일한다. 포트 변경·시크릿 창·다른 브라우저도 저장 영역이 달라진다.

## 6. 검증 범위

자동 테스트 37개는 지정 데모 계정과 잘못된 자격 증명 거부, 이전 로그인 무효화, 회원 화면 직접 접속 차단, 비로그인 React 렌더링의 회원 메뉴 숨김, 두 페이지 체험과 안내 거절 후 3쪽부터 읽기, 새로고침과 책 완독 후 다른 관점 추천, 게스트·회원의 동일한 추천과 추천 소진 처리, 이전 페이지 이동과 중복 집계 방지, 완독 화면의 실제 완독 여부, 시간 목표의 페이지 목표 전환, 기존 독서·추천·저장 기능을 확인한다. TypeScript와 프로덕션 빌드도 확인한다. 실제 브라우저에서 버튼을 누르는 자동 E2E 테스트는 구성되어 있지 않다.

실제 인증 서버를 붙일 때는 `AppContext.login()`과 초기 로그인 상태 복원 지점을 서버 세션 확인으로 교체해야 한다. 현재 브라우저 상태는 데모용이며 사용자별 계정 데이터 분리도 구현하지 않는다.

## 7. 이전 페이지와 읽기 완료 집계

독서 하단의 이전 페이지는 책의 첫 페이지까지 이동할 수 있으며 첫 페이지에서는 비활성화된다. `retreat()`는 현재 위치와 스크롤만 바꾸고 읽기 기록, 원래 읽을 분량, 두 페이지 체험 범위를 바꾸지 않는다. 체험 후 계속 읽기를 선택한 사용자는 3쪽에서 2쪽·1쪽으로 돌아갈 수 있다. 저장 상태 복원에서도 현재 위치가 원래 시작점보다 앞이라는 이유로 시작점을 바꾸지 않는다.

본문 화면의 위쪽 쪽수, 아래쪽 '현재 읽는 위치', 진행 막대는 모두 현재 펼친 페이지로 통일했다. 4쪽이면 모두 4 / 10쪽을 기준으로 표시하며 이전 페이지로 돌아가면 함께 바뀐다. 별도의 '읽기 완료 3 / 10쪽' 표시는 혼동을 줄이기 위해 본문에서 제거했다.

독서 기록은 계속 '읽고 다음' 또는 완료 버튼으로 확인한 고유 페이지를 집계한다. 처음 1쪽을 펼치면 내부 완료 수는 0이며, '읽고 다음'을 누르면 1쪽을 기록하고 2쪽을 연다. 이전 페이지로 이동해도 완료 기록은 지워지지 않으며 같은 페이지를 다시 완료해도 책의 전체 완료 수는 중복 증가하지 않는다. 마지막 페이지도 완료 버튼을 눌러야 실제 완독으로 처리된다. 다른 날 재독하면 해당 날짜의 독서 기록은 남지만 책 전체 완료 수는 중복 증가하지 않는다. 판본이 다르거나 범위를 벗어난 페이지는 해당 책의 완료 수에 포함하지 않는다.

## 8. 하루 목표는 페이지 기준

홈의 목표 변경과 초기 추천 설정은 하루 1·3·5·10페이지 중에서 선택한다. 시간 단위 목표는 제거했으며 목표 달성 여부는 실제 읽음 처리한 페이지로만 계산한다. 이전에 저장한 시간 목표는 저장 상태 복원 시 기본 3페이지로 전환한다. 분과 페이지는 대응 관계가 없으므로 10분을 10페이지로 옮기지 않는다. 기존 페이지 목표와 독서 기록은 유지한다. 예상 소요 시간 안내와 내부 독서 시간 기록은 목표 판정에 사용하지 않는다.
